# Enrich Vigilante Spec

Use when a request is valuable but underspecified.

## Steps

1. Identify the target user, business outcome, and affected workflow.
2. State the current behavior and the desired behavior.
3. Capture non-goals, constraints, and external dependencies.
4. Define acceptance criteria as observable behavior.
5. Add failure cases for Google APIs, Maps pages, GBP access, browser automation,
   webhooks, notifications, and permissions when relevant.
6. Recommend the OpenSpec capability or change name.
7. Produce a concise markdown brief that can feed `/opsx:propose`.
